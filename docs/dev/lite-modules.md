# MakeCountryLite と機能パックの設計

このリポジトリの同じソースから、次の 3 種類を配布する。

| 配布物 | 内容 |
| --- | --- |
| **MakeCountry** (フル版) | 従来どおり 1 つのビヘイビアパックにすべての機能を入れたもの。配布を継続する |
| **MakeCountryLite** | 建国と経済の基本だけのビヘイビアパック |
| **機能パック** | Lite に足すと、フル版と同じ遊び方になるビヘイビアパック群 |

リソースパックは 3 種類とも共通の MakeCountryResourcePack を使う。

## パックの分け方

| パック | ID | 入るもの |
| --- | --- | --- |
| Lite | `lite` | 国・土地・ロール・プロット・外交・戦争・税金・国庫・お金と送金・ホーム/TPA・チャット・メニュー・管理者機能・ショップ/マーケット/取引・スマホ |
| 職業 | `jobs` | 職業・職業レベル・報酬・ランキング |
| 料理 | `cooking` | 料理・調理器具・食材・作物 |
| 生産 | `industry` | 鍛冶・化学・鉱物・バイオーム・梱包・圧縮ブロック |
| 釣り | `fishing` | 釣り・魚・魚図鑑 |
| 装飾 | `deco` | 家具・和服・スーツ・刀・ネオン |
| 生活 | `life` | 結婚・懸賞金・二つ名・バックパック |

## データの持ち方

ダイナミックプロパティはアドオン (manifest の UUID) ごとに別の領域になる。
パックが別になると、他のパックが保存したデータは直接読めない。

- **Lite はフル版と同じ UUID を使う。** フル版から乗り換えると、Lite はフル版のデータ (国・土地・プレイヤー・お金・職業レベルなど) をそのまま読める。
  フル版と Lite は同時に入れない (同じ UUID なので Minecraft が片方しか読み込まない)。
- **機能パックは自分の UUID を持ち、自分のデータは自分の領域に保存する。**
- **他のパックからその場で読む必要がある値は、スコアボードにも書き出す。** スコアボードはパックをまたいで共有される。
  - お金: `mc_money` (Lite が書き、他は読むだけ)
  - 職業レベル: `mcjob_<職業ID>` (職業パックが書き、料理・生産・釣りが読む)
- **変更は持ち主のパックに依頼する。** お金の増減は Lite、職業経験値の加算は職業パックが行う。

## パック同士のやり取り (scriptevent)

すべて `system.sendScriptEvent` で送り、受け取る側は `ScriptEventSource.Server` 以外 (プレイヤーの /scriptevent など) を無視する。
メッセージは JSON。1 通の上限 (2048 文字) を超える場合は分割する。

| ID | 向き | 内容 |
| --- | --- | --- |
| `makecountry:hello` | 全体へ | `{ pack, version, protocol }` 起動時と `discover` を受けたときに名乗る |
| `makecountry:discover` | 全体へ | 起動中のパックに名乗りを求める |
| `makecountry:rpc` | 指定のパックへ | `{ id, from, to, method, args }` 依頼。返事が要るもの |
| `makecountry:rpc_result` | 依頼元へ | `{ id, to, ok, value \| error }` |
| `makecountry:event` | 全体へ | `{ from, name, data }` 通知。返事は要らない |
| `makecountry:chunk` | 指定のパックへ | `{ id, to, seq, total, data }` 長いメッセージの分割 |

### 主な依頼・通知

| 名前 | 持ち主 | 内容 |
| --- | --- | --- |
| `economy.add` / `economy.remove` | Lite | プレイヤーの所持金の増減 (理由付き)。残高不足は失敗を返す |
| `perm.check` | Lite | 場所と権限名から、その操作が許可されるか |
| `country.of` | Lite | プレイヤーの所属国 |
| `jobs.reward` | 職業 | 職業の行動に対する報酬 (経験値とお金) |
| `ui.open` | 各パック | メニューから機能パックのフォームを開く |
| `migrate.request` / `migrate.data` | Lite → 各パック | フル版時代のデータの引き継ぎ |

### 検知

- 各パックは `worldLoad` 後に `hello` を送る。Lite は起動中のパック一覧を持ち、メニューに機能パックのボタンを出す。
- 機能パックは Lite の `hello` が来ないとき、ログインしたプレイヤーに「MakeCountryLite が必要です」と知らせる。

### 引き継ぎ

フル版から Lite に乗り換えたワールドでは、フル版の職業レベルなどが Lite の領域に残っている。
機能パックは初回起動時とプレイヤーのログイン時に `migrate.request` を送り、Lite が旧データを読んで `migrate.data` で送る。
受け取ったパックは自分の領域に保存し、Lite に完了を通知する。Lite はその旧データを消さずに「引き継ぎ済み」の印を付ける。

## 決定事項 (2026-11-16)

- 生活パックには結婚・懸賞金も入れる。結婚・懸賞金のデータ (配偶者・共有財布・懸賞金) は生活パックが持ち、
  所持金の移動や共有ホームへのテレポートは Lite に依頼する。
- 職人系 (料理・鍛冶・化学) の制作では、完成品はすぐ渡し、報酬 (お金・経験値) は職業パックへ依頼する。
  届かなかった報酬は制作側のパックに保存し、職業パックが起動したときに支払う。依頼には ID を付け、二重に払わない。
  職業パックが入っていない場合、報酬は無し。
- フル版は同じソースを従来どおり 1 パックとしてビルドする (`src/index.ts`)。

## 実装の方針

- Lite から機能パックを呼ぶところは `src/shared/hooks.ts` の差し込み口にする。
  フル版では機能のコードが直接差し込み口に登録し、分割版では Lite が scriptevent で機能パックへ転送する。
- 機能パックから Lite・職業パックのデータを使うところは、同じ使い方のまま中身だけ依頼に置き換えた部品
  (`src/remote/`) をビルド時に差し替える (tsdown の alias)。元のコードはなるべく変えない。

## ソースとビルド

- ソースは `src/` を共通で使う。パックごとの入口は `src/packs/<ID>/index.ts`。
- フル版の入口は従来どおり `src/index.ts`。フル版ではすべての機能が同じパック内にあるので、依頼は直接呼び出しになる。
- 機能の呼び出しは `src/shared/services/` のインターフェース経由にする。
  フル版と Lite では「直接」実装を、機能パックでは「scriptevent / スコアボード」実装を登録する。
- パックごとの manifest とブロック・アイテムなどの JSON 資産は `packs/<ID>/` に置き、ビルド時に `dist/<ID>/` へまとめる。
